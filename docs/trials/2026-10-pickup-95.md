# Trial: pick up Grok Bot's PR #95

The goal of universal-harness is that an agent can take over work another agent
started without a long explanation. This trial measures that on real work: Grok Bot's
unfinished [sv-pro/ai2rules#95](https://github.com/sv-pro/ai2rules/pull/95), picked up
by a fresh Claude Code session and a fresh Codex session, with nothing but a one-line
prompt and what is in the repo.

**Primary measure:** how many questions the agent had to ask you, and how many wrong
things it said. **Secondary:** the checklist score and time to a full answer.

handoff block, `.uh/brief.md` and `.mcp.json`; `uh provision --check` up to date;
ground truth refreshed (only change: #95 is now 1 commit behind `main`). Linear is
**not connected** at setup time; if you connect it before the sessions, record that
in section 6.

1. Merge [sv-pro/ai2rules#96](https://github.com/sv-pro/ai2rules/pull/96). Without it,
   `main` has no handoff block and no `.uh/brief.md`.
2. Decide whether Linear is connected (`/mcp` in Claude Code, see
   `docs/claude-code-linear.md`). Either way is a valid trial; record which.
3. Clear the stage in ai2rules. The fix branch's uncommitted `HANDOFF.md` is untracked,
   so it would follow you to `main` and could be read as #95's handoff:

   ```bash
   git -C C:\Users\imser\workspace\ai2rules stash push --include-untracked -m fix-branch-HANDOFF -- HANDOFF.md
   ```

   ```bash
   git -C C:\Users\imser\workspace\ai2rules switch main
   ```

   ```bash
   git -C C:\Users\imser\workspace\ai2rules pull --ff-only
   ```

   Do **not** check out #95's branch: finding it is part of the test.
4. Refresh the ground truth (section 4) in case #95 moved since 2026-10-02:

   ```bash
   uh pickup "#95" -p ai2rules
   ```

### Run notes (2026-10-02, run by Claude Code with subagents)

**How the runs differ from the plan.** Both were Claude Code subagents, not
interactive sessions: a subagent's shell is WSL, so the prompt added set-up notes (repo
path, run Windows tools via `cmd.exe`, without naming `uh`), and told it to read
`CLAUDE.md` and its imports first, since it did not start in the repo. A subagent
cannot ask mid-run, so questions are the ones in its final answer. Phase 2 was not run.

**A (main with #96).** Followed the handoff block: read `CLAUDE.md`, `AGENTS.md`,
`.uh/brief.md`, then `uh pickup 95 --no-fetch`. From pickup it took identity, last
agent, branch position, draft state and checks, PR description, missing handoff
records, Linear unreadable, and the next transition's gates; then verified live state
with `gh`. It chose `--no-fetch` after **reading the harness source** to find out
whether pickup writes anything (`uh` has no `--help`). Changed nothing in the repo.
Left one file in Windows `%TEMP%` (deleted afterwards).

**C (detached at 41a4eda, before #96).** Not a clean baseline: the repo's `main`
already has #96. Nothing on the PR said "Grok Bot" (commits say "Cursor Agent"), the
reflog showed a checkout of an older commit minutes earlier, so the agent concluded its
instructions were stale, diffed against `main` and read `main:.uh/brief.md` and the
handoff block with `git show`. From them it took the `cursor/` = Grok Bot mapping, where
handoff records live, the change flow's gates and the obligations. It did **not** run
`uh`: the block says "If `uh` is installed" and calls the tool "not published", and it
never checked (`where uh`), which it called an oversight. It also noticed the detached
HEAD and the unrelated stash and left both alone.

**Both runs are contaminated by the parent session's memory.** C's debrief cites "the
user's memory note" on ai2rules conventions: subagents see the orchestrating session's
auto-memory, which describes AGENTS.md, HANDOFF.md and `_tasks` as the handoff
conventions. A fresh session in the repo would not have that.

**Beyond the ground truth** (both runs; checked items marked ✓):
- ✓ #84, #85, #86 are still open on GitHub although #92–#94 merged them: the
  trackers-sync obligation already failed once on this parent. (Ground truth missed it.)
- ✓ The "review fixes" commit answers a review that does not exist on GitHub.
- ✓ `modern_per_project_off_file_enabled` writes the *global* switch file; the
  per-project switch is untested.
- Several tests assert current behaviour where it differs from #87, beyond the 3
  flagged (missing bash, missing `claude`, fake echo hook, duplicates); not checked.
- The "nothing is executed" proof is weak. A and C disagree on why (trap scripts would
  loop on a fake `bash` vs the trap `harness` is never selected); not checked.
- C only: README test counts not updated (O8), `#![cfg(unix)]` means no Windows run,
  #87 contradicts itself on missing `claude`, possible FIFO hang in doctor itself.

**Questions to the maintainer** (both ~5, none answerable from the repo): continue on
Grok Bot's branch or a new `claude/` branch; spec vs code for each mismatch; test hooks
in `src/` for the error cases; where the "review" came from; AI2-25's Linear status
and closing #84–#86 on both trackers. They fall into three kinds:
- **policy the manifest could state:** which branch to continue on; whether to close
  issues whose PRs merged (the trackers-sync obligation already says so);
- **facts another agent could supply:** AI2-25's Linear status (any agent with Linear
  access); where the "review" came from (Grok Bot, who did the review fixes);
- **maintainer decisions:** spec vs code, scope of test hooks, merging.

### Reading against the hypotheses (section 7)

- **O7 missed by both** (merging #95 must not close #87): pickup should show
  "Part of" vs "Closes" from the PR body.
- **O8 missed by A, caught by C** (test counts): pickup could check obligations against
  the files a PR changes.
- **A ≈ C in score, C slightly faster:** the hypothesis "the block and `uh` add little"
  is **not** supported, because C used the block and brief anyway (from `main`) and
  needed them for the Grok Bot mapping and the records. What did not pay off is `uh`
  itself: A spent part of its time reading the harness source to confirm pickup is
  read-only, and C skipped it. Fixes: `uh --help` stating what each command reads and
  writes; the block should say how to check for `uh` instead of "if installed".
- **Tracker drift is real:** #84–#86 open after their PRs merged. Pickup on a parent key
  could list children whose PR merged while the issue is still open.
- **Method:** a clean rerun needs a session without the parent's memory, started in the
  repo (e.g. Codex via `codex exec` for B, or an interactive session), and a clean
  baseline needs a clone without #96.
